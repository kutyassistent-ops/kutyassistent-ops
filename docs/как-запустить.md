## utility-billing — учёт ЖКУ

```bash
cd utility-billing
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

Открыть <http://127.0.0.1:5000>, зарегистрировать пользователя с ролью `owner`.

Переменные окружения (см. `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | значение для разработки | подпись сессий, задайте своё |
| `DB_PATH` | `billing.db` | путь к файлу SQLite |

> В репозитории **нет** рабочей базы: файл `*.db` исключён `.gitignore`,
> потому что содержит реальные учётные записи и показания. База создаётся
> автоматически при первом запуске; схема — `docs/schema.sql`.

## shopping-list-demo

```bash
cd shopping-list-demo
python -m venv .venv && .venv\Scripts\activate     # Linux: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Открыть <http://127.0.0.1:5000> — редирект на демо-список. Данные хранятся
в памяти и исчезают при перезапуске; это учебный пример, а не готовое
приложение.

## grafana-bitrix-relay (Linux)

По умолчанию relay читает `/etc/bitrix-relay.json`, но путь переопределяется
переменной окружения `BITRIX_RELAY_CONFIG` — это удобно для локального запуска
без установки:

```bash
cp bitrix-relay.example.json relay.json
vi relay.json                            # portal, token, port, получатели

BITRIX_RELAY_CONFIG=./relay.json python3 bitrix-relay.py
```

Для службы на сервере путь остаётся стандартным:

```bash
sudo install -m 0640 bitrix-relay.example.json /etc/bitrix-relay.json
sudo chown root:nogroup /etc/bitrix-relay.json
sudo vi /etc/bitrix-relay.json           # вписать portal и token
```

Проверка доставки мимо Grafana:

```bash
curl -s -X POST http://127.0.0.1:9098/notify \
  -H "Content-Type: application/json" \
  -d '{"status":"firing","alerts":[{"labels":{"alertname":"test"},"annotations":{"summary":"Проверка"}}]}'
```

Как службу — через `bitrix-relay.service` (инструкция в README проекта).

## MikoPBX_Prometheus

1. Взять `dist/ModulePrometheus-1.4.3.zip`.
2. Админка MikoPBX → **Модули расширения → Загрузить новый модуль**.
3. Включить модуль, открыть настройки: адрес прослушивания, порт (по умолчанию
   9713), список разрешённых адресов.
4. Добавить job в `prometheus.yml`:

```yaml
scrape_configs:
  - job_name: mikopbx
    scrape_interval: 60s
    static_configs:
      - targets: ['192.168.1.10:9713']
```

Проверка: `curl -s http://192.168.1.10:9713/metrics | head`.

## MikoPBX_birix_notify

1. Взять `dist/ModuleBitrixNotify-2.0.10.zip`.
2. **Модули расширения → Загрузить новый модуль** → выбрать zip → включить.
3. Битрикс24 → **Разработчикам → Другое → Входящий вебхук**, права `im`,
   скопировать полный URL `https://<портал>/rest/<индекс>/<токен>/`.
4. В настройках модуля вставить URL, задать карту «номер = ID сотрудника».
5. Проверить кнопкой «Тестовое сообщение».

Токен хранится только в настройках/файле `/etc/bitrix-webhook-token`,
в репозиторий не попадает.

## grafana-dashboards

Файлы дашбордов — ресурсы Grafana v2 (`apiVersion: dashboard.grafana.app/v2`).
Кладутся в каталог provisioning:

```bash
cp "MikoPBX/MikoPBX — АТС.json" \
   /var/lib/grafana/dashboards/Телефония/mikopbx-pbx.json
systemctl restart grafana-server
```

Через API (Grafana 12+): `POST /api/v2/dashboards` с Bearer-токеном.
Импорт через «Dashboards → Import» для этого формата **не работает**.

Проверка целостности выгрузок:

```bash
python tools/validate_dashboards.py
```

## usb-watchdog (Windows)

```powershell
cd usb-watchdog
Unblock-File .\scripts\WatchDog.ps1

.\scripts\WatchDog.ps1 -Status          # проверить связь и параметры
.\scripts\WatchDog.ps1 -Armed           # взвести таймер
.\scripts\WatchDog.ps1 -Watch -Armed -IntervalSec 60   # постоянный heartbeat
```

Драйвер нужен только для Windows 7: `.\scripts\Install-Driver.ps1`
(от администратора). Автозапуск: `.\scripts\Register-Task.ps1`.

> Проверка `-Test Reset` реально перезагружает компьютер.
