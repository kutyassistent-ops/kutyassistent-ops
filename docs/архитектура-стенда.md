# Архитектура стенда

Один узел мониторинга обслуживает телеком-станцию, сеть печати и камеры.
Все проекты — части этой схемы либо самостоятельные утилиты.

## Схема

```
┌────────────────────┐        ┌──────────────────┐        ┌─────────────────┐
│   MikoPBX (АТС)    │        │   Prometheus     │        │     Grafana     │
│  192.168.2.77      │ scrape │  (сбор метрик)   │ PromQL │  дашборды +     │
│                    │───────▶│                  │───────▶│  алерты         │
│  ModulePrometheus  │ :9713  │  jobs: mikopbx,  │        │  + provisioning │
│  ModuleBitrixNotify│        │  printers_snmp,  │        └────────┬────────┘
└─────────┬──────────┘        │  cctv-cameras    │                 │ webhook
          │ im.notify         └──────────────────┘                 ▼
          │                                              ┌────────────────────┐
          │                                              │  bitrix-relay.py   │
          │                                              │  :9098/notify      │
          │                                              └─────────┬──────────┘
          │                                                        │ form-encoded
          ▼                                                        ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                              Битрикс24                                  │
│                    личные сообщения / чат отдела                        │
└─────────────────────────────────────────────────────────────────────────┘
```

## Потоки данных

| Что | Откуда | Куда | Как |
|---|---|---|---|
| Метрики АТС | `ModulePrometheus` | Prometheus | `GET /metrics`, порт 9713, text exposition 0.0.4 |
| Метрики принтеров | SNMP-экспортёр | Prometheus | `up{job="printers_snmp"}` |
| Доступность камер | `blackbox_exporter` | Prometheus | `probe_success == 0` |
| Дашборды | Prometheus | Grafana | PromQL, переменные `loc`, `prt`, `site`, `nvr` |
| Алерты | Grafana | Grafana Alerting | правила с contact point `webhook` |
| Уведомления об алертах | Grafana | Битрикс24 | `POST` JSON на relay, relay → `im.notify` |
| Уведомления о звонках | `ModuleBitrixNotify` | Битрикс24 | `im.notify` напрямую из модуля |
| Перезагрузка сервера | `usb-watchdog` | материнская плата | замыкание Reset/Power |

## Почему relay, а не прямой webhook

Grafana умеет отправлять webhook напрямую, но в Битрикс24 `im.notify`:

1. не принимает JSON — только `application/x-www-form-urlencoded`;
2. требует percent-кодирования кириллицы в шаблонах, а Grafana подставляет
   значения как есть;
3. не резолвит имя хоста из контейнера — нужен IP docker-моста.

Relay решает все три пункта и заодно ведёт журнал доставки. Подробности —
[grafana-bitrix-relay](https://github.com/kutyassistent-ops/grafana-bitrix-relay).

## Отдельный контур: watchdog

USB WatchDog Pro2 не участвует в мониторинге. Это аппаратная страховка:
если сервер завис так, что не отвечает ни по сети, ни локально, таймер сам
замыкает контакты Reset/Power. Управляется скриптом
[usb-watchdog](https://github.com/kutyassistent-ops/usb-watchdog), который
шлёт heartbeat по виртуальному COM-порту.

Схема и протокол — [docs/01-устройство.md](https://github.com/kutyassistent-ops/usb-watchdog/blob/main/docs/01-устройство.md).
